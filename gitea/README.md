**注意事項**

初期設定後のページ遷移で下記のエラーが表示されるが問題ない。

> Frontend is not initialized, check console errors or asset files.

エラーの原因は、初期設定によって gitea の Base URL が切り替わるが、初期設定した後のページ遷移は初期設定前の URL が引き継がれて不整合を起こしている模様。
これ以降は初期設定後の Base URL を使うこと。

|            | Base URL                     | 備考                       |
| :--------- | :--------------------------- | :------------------------- |
| 初期設定前 | http://localhost:3000/       |                            |
| 初期設定後 | https://my-server.local/git/ | 初期設定画面で入力した URL |

ユーザー認証の設定

### 2要素認証 (TOTP) の有効化

> TOTP = Time-based One-Time Password

2要素認証を有効にするユーザーでサインインする。

右上のアイコン > 設定 > セキュリティ > 2要素認証 (TOTP) > 2要素認証の開始 を開く。

表示される QR コードを認証アプリで読み取る。

次に、認証アプリに表示されているパスコードを入力する。


クライアント側の設定
----------------------------------------

### TSL 認証の設定

> この設定はクライアント（PCユーザー）毎に実施する。

Windows 環境の Git で HTTPS 接続時の TLS 認証の方法を設定する。
Windows の認証局ストアを使う方法と OpenSSL を使う方法の 2 つから選択する。

| http.sslBackend 設定値 | 説明                                               |
| :--------------------- | :------------------------------------------------- |
| schannel               | Windows の認証局ストアに登録された証明書を使用する |
| openssl                | OpenSSL ＋ 証明書ファイル を使用する               |


#### （方法1） Windows の認証局ストアを使用する（トラブル未解決）

git を使用する Windows ユーザーでコマンドプロンプトを起動して、下記のコマンドを実行する。

```dps
git config --global http.sslBackend schannel
```

**発生したトラブル**

> fatal: unable to access 'https://my-server.local/git/...': The requested URL returned error: 400

400 エラーが発生した。
原因は不明。
mTLS のクライアント認証に失敗している可能性あり。


#### （方法2） OpenSSL を使用する

（前提）  
証明書ファイルのファイルパス

| 証明書                         | ファイルパス                                  |
| :----------------------------- | :-------------------------------------------- |
| ルート証明書（証明書チェーン） | C:/work/nginx-env/CA/keys_public/ca_chain.crt |
| クライアント証明書             | C:/work/nginx-env/CA/keys_public/client.crt   |
| クライアント秘密鍵             | C:/work/nginx-env/CA/keys_secret/client.key   |

（操作）  
git を使用する Windows ユーザーでコマンドプロンプトを起動して、下記のコマンドを実行する。

```dps
git config --global http.https://my-server.local.sslBackend openssl
git config --global http.https://my-server.local.sslCAInfo  C:/work/nginx-env/CA/keys_public/ca_chain.crt
git config --global http.https://my-server.local.sslCert    C:/work/nginx-env/CA/keys_public/client.crt
git config --global http.https://my-server.local.sslKey     C:/work/nginx-env/CA/keys_secret/client.key
```

（補足）  
コマンド実行後は .gitconfig に下記が追記される。

> C:\\Users\\ユーザ名\\.gitconfig
> 
> ```ini
> [http "https://my-server.local"]
> 	sslBackend = openssl
> 	sslCAInfo = C:/work/nginx-env/CA/keys_public/ca_chain.crt
> 	sslCert = C:/work/nginx-env/CA/keys_public/client.crt
> 	sslKey = C:/work/nginx-env/CA/keys_secret/client.key
> ```


#### （共通） OAuth 認証の実施

1. git クライアントにてサーバとの通信が発生する操作を行う。（例： clone, pull, push ）
    
    ブラウザが開いて404エラーが表示される。
    > https://my-server.local/login/oauth/authorize?...
    > 
    > ```text
    > 404 Not Found
    > ```

2. ブラウザで開いたページの URL の `/login/` を `/git/login/` に書き換えて開きなおす。 
    
    > https://my-server.local/login/oauth/authorize?...

    ↓
    
    > https://my-server.local/git/login/oauth/authorize?...
    > 
    > ```text
    > "Git Credential Manager"にあなたのアカウントへのアクセスを許可しますか？
    > アクセスを許可すると、このアプリケーションは、プライベート リポジトリや組織を含むあなたのすべてのアカウント情報に対して、アクセスと書き込みができるようになります。
    > このアプリケーションは Gitea: Git with a cup of tea が作成しました。
    > スコープ:
    > 
    > このアプリケーションを許可すると http://127.0.0.1:59869/ にリダイレクトします。
    > 
    > アプリケーションを許可  キャンセル
    > ```

3. 「アプリケーションを許可」を押下する。
    
    http://127.0.0.1:xxx/ にリダイレクトされる。接続エラーになるが問題なし。  
    ブラウザ外に認証ダイアログが表示される。

4. ユーザ名とパスワードを入力する。
5. 完了。


#### （補足） OAuth 認証情報の削除方法

1. 「資格情報マネージャー」を開く。
2. 「Windows 資格管理」の「汎用資格情報」にある `git:https://my-server.local` を削除する。


#### （補足） トラブルシューティング

* SSL certificate problem: unable to get local issuer certificate
    
    > ```
    > fatal: unable to access 'https://my-server.local/git/...': SSL certificate problem: unable to get local issuer certificate
    > ```
    
    原因： sslCert または sslCAInfo が正しく設定できていない。
    
    対策： sslCert または sslCAInfo の設定を見直す。

* unable to set private key file: 'C:/work/nginx-env/CA/keys_public/client.crt' type PEM
    
    > ```
    > fatal: unable to access 'https://my-server.local/git/...': unable to set private key file: 'C:/work/nginx-env/CA/keys_public/client.crt' type PEM
    > ```
    
    原因： sslKey が正しく設定できていない。
    
    対策： sslKey の設定を見直す。

* HTTP 413 エラー
    
    > ```
    > Enumerating objects: xxx, done.
    > Counting objects: 100% (xxx/xxx), done.
    > Delta compression using up to xxx threads
    > Compressing objects: 100% (xxx/xxx), done.
    > error: RPC failed; HTTP 413 curl 22 The requested URL returned error: 413
    > （中略）
    > fatal: the remote end hung up unexpectedly
    > ```
    
    原因： クライアントからの送信データが大きすぎる。
    
    対策： nginx の client_max_body_size の設定値を大きくする。

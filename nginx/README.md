nginx
========================================

nginx でリバースプロキシを構築して mTLS 認証を実装する。


事前準備
----------------------------------------

* nginx の zip ファイル（[nginx-x.xx.xx.zip](https://nginx.org/en/download.html)）を nginx フォルダ直下に展開すること
* CA と サーバ証明書 と クライアント証明書 を作成すること
* クライアントに CA と クライアント証明書 をインストールすること


nginx の起動・終了（手動）
----------------------------------------

nginx の設定ファイルは nginx の実行環境とは別に管理するため `-c` オプションで設定ファイルを指定する。

|                      | パス                          |
| :------------------- | :---------------------------- |
| nginx の実行ファイル | `\nginx\nginx.exe`            |
| nginx の設定ファイル | `\nginx-conf\conf\nginx.conf` |


### nginx の起動

```dos
start .\nginx.exe -c ..\nginx-conf\conf\nginx.conf
```


### nginx の停止

```dos
.\nginx.exe -s quit -c ..\nginx-conf\conf\nginx.conf
```


### nginx の強制終了

```dos
.\nginx.exe -s stop -c ..\nginx-conf\conf\nginx.conf
```


### nginx の再起動

```dos
.\nginx.exe -s reload -c ..\nginx-conf\conf\nginx.conf
```


nginx の起動・終了（自動）
----------------------------------------

### nginx の自動起動

t.b.d.


### nginx の自動停止

t.b.d.

nginx.conf の設定項目
----------------------------------------

### http 通信 (port 80)

http 通信の設定は `listen 80` の区画に記述する。
削除（コメントアウト）すると受け付けなくなる。

```conf
# server {
#     listen       80;
#     ...
# }
```


### http 通信 (代替ポート)

http 通信の設定は `listen xxx` の区画に記述する。
削除（コメントアウト）すると受け付けなくなる。

```conf
# server {
#     listen       8000;
#     listen       somename:8080;
#     ...
# }
```


### https 通信 (port 443)

https 通信の設定は `listen 443 ssl` の区画に記述する。
削除（コメントアウト）すると受け付けなくなる。

```conf
server {
    listen       443 ssl;
    server_name  my-server.local;
    ...
}
```


#### TLS 認証用の設定（サーバ証明書）

| キー                | 値                                    | 説明                               |
| :------------------ | :------------------------------------ | :--------------------------------- |
| ssl_certificate     | ../../CA/keys_public/server_chain.crt | 中間 CA ＋ サーバ証明書 のチェーン |
| ssl_certificate_key | ../../CA/keys_secret/server.key       | サーバの秘密鍵                     |


#### mTLS 認証用の設定（クライアント証明書）

| キー                   | 値                                | 説明                                                     |
| :--------------------- | :-------------------------------- | :------------------------------------------------------- |
| ssl_client_certificate | ../../CA/keys_public/ca_chain.crt | ルート CA ＋ 中間 CA のチェーン                          |
| ssl_verify_client      | on                                | mTLS 認証の要否（on：必須、off：オプション）             |
| ssl_verify_depth       | 2                                 | クライアント証明書を検証する際の証明書チェーン検証の深さ |


#### location 設定

| キー           | 値       | 説明                                 |
| :------------- | :------- | :----------------------------------- |
| location /     | 下記参照 | WEB サーバの設定                     |
| location /git/ | 下記参照 | gitea サーバへのリバースプロキシ設定 |


**location / の設定値**

| キー  | 値                   | 説明                                     |
| :---- | :------------------- | :--------------------------------------- |
| root  | html                 | ドキュメントルートのパス                 |
| index | index.html index.htm | `/` にアクセスしたときに表示するファイル |


**location /git/ の設定値**

| キー                 | 値                                         | 説明                                                 |
| :------------------- | :----------------------------------------- | :--------------------------------------------------- |
| proxy_pass           | http://localhost:3000/                     | 転送先のアドレス                                     |
| proxy_set_header     | Host $host                                 | プロキシが追加するヘッダー                           |
| proxy_set_header     | X-Real-IP $remote_addr                     | プロキシが追加するヘッダー： リモートの IP アドレス  |
| proxy_set_header     | X-Forwarded-For $proxy_add_x_forwarded_for | プロキシが追加するヘッダー                           |
| proxy_set_header     | X-Forwarded-Proto $scheme                  | プロキシが追加するヘッダー                           |
| client_max_body_size | 50M                                        | クライアントから受信するリクエストボディのサイズ上限 |


トラブルシューティング
========================================

ブラウザからのアクセス時
----------------------------------------

### 申し訳ございません。このページに到達できません (ERR_CONNECTION_TIMED_OUT)

> エラーメッセージ（例）：
> 
> ```text
> 申し訳ございません。このページに到達できません
> my-server.local の応答に時間がかかりすぎました
> お試しください:
> 
> 接続を確認してみてください
> プロキシとファイアウォールの確認
> ERR_CONNECTION_TIMED_OUT
> ```

**想定される原因**

* nginx が動作していない
* ファイアウォールでブロックされている

**確認手順**

* アクセスログを確認する
  * アクセスログに記録が残ってない場合はファイアウォールで止められている可能性が高い。
* nginx を（再）起動する


#### ファイアウォールでブロックされている場合

1. 「Windows ファイアウォールによるアプリケーションの許可」を開く
2. 「許可されたアプリおよび機能」のリストから nginx を探す
3. nginx を選択して「詳細」ボタンを押下して nginx のパスが意図したものか確認する
4. nginx を許可に変更する

**注意事項**

「許可されたアプリおよび機能」のリストは実行ファイルのパス単位で管理される。
nginx の配置フォルダを変更する都度、ファイアウォールの許可が必要になる。
その場合、移動前のパスの設定を削除すること。（自動で削除されない）


### 接続がプライベートではありません (ERR_CERT_AUTHORITY_INVALID)

> エラーメッセージ（例）：
> 
> ```text
> 接続がプライベートではありません
> 攻撃者が、my-server.local から個人情報 (パスワード、メッセージ、クレジットカードなど) を盗み取ろうとしている可能性があります。
> net::ERR_CERT_AUTHORITY_INVALID
> ```

**想定される原因**

* サーバ証明書の正当性を証明できない。

**確認手順**

1. クライアント PC の認証局ストアにルート証明書が入っていることを確認する
   1. 「ユーザー証明書の管理」を開く
   2. 「信頼されたルート証明機関」＞「証明書」のリストを探す
2. サーバ証明書がルート証明書のチェーンで署名されていることを確認する
   1. サーバ証明書をダブルクリックで開く
   2. 「証明のパス」タブを開いて証明書チェーンを確認する


### 400 Bad Request

> エラーメッセージ（例）：
> 
> ```text
> 400 Bad Request
> No required SSL certificate was sent
> ```

**想定される原因**

* クライアント PC にクライアント証明書が入っていない

**確認手順**

1. クライアント PC の認証局ストアにクライアント証明書が入っていることを確認する
   1. 「ユーザー証明書の管理」を開く
   2. 「個人」＞「証明書」のリストを探す
2. クライアント証明書がルート証明書のチェーンで署名されていることを確認する
   1. クライアント証明書をダブルクリックで開く
   2. 「証明のパス」タブを開いて証明書チェーンを確認する
